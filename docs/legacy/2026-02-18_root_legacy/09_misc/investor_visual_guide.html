3. Vivid는 무엇을 만드는가? — "AI 조감독 OS"

"감독이 머릿속에 떠올린 영감을 던지면,
AI가 영화를 설계해주는 조감독 시스템"

영화·드라마·광고를 만들 때 감독 옆에는 항상 조감독(Assistant Director)이 있습니다. 조감독은 감독의 의도를 파악하고, 촬영 순서를 짜고, 스태프에게 지시를 내리는 사람입니다. Vivid는 이 역할을 AI가 대신하도록 만드는 제품입니다.

🧑 감독 (사람)

  • 💭 영감이 떠오름
  • 📱 텔레그램에 사진·영상 전송
  • 📝 노션에 씬 메모 작성
  • 👍 AI 제안을 승인/수정/기각

🤖 AI 조감독 (Vivid)

  • 📥 입력 수집 및 통합
  • 🧠 씬 분석 + 감정선 파악
  • 🎯 최적 샷 추천
  • 📋 엔진별 프롬프트 자동 작성
  • 🎬 프리뷰 영상 생성
쉬운 비유: 카카오택시가 기사를 AI로 대체한 게 아니라, "내비게이션"이라는 AI 조감독을 줘서 누구나 길을 잘 찾게 해준 것과 같습니다. Vivid는 영상 제작의 내비게이션입니다.
🧠

4. 핵심 기술 구조 — 비개발자를 위한 설명

Vivid의 기술을 음식점에 비유하면 이렇습니다:

📥
주문 접수 (입력 수집)
텔레그램·노션·웹에서 감독의 영감을 받아 하나로 통합. 카톡·메일·메모 등 여기저기 흩어진 아이디어를 한 곳으로.
📒
레시피북 (메모리 시스템)
감독의 취향·과거 작업·선호 스타일을 기억. AI가 감독을 오래 알수록 더 정확하게 추천 (넷플릭스 추천과 유사).
🔬
맛 분석가 (Gemini 3 Pro)
구글의 최신 AI가 장면의 구조·감정·전후 맥락을 이해. "이 장면은 슬픈 분위기니까 다음은 이렇게" 판단.
📚
재료 창고 (TwelveLabs + Qdrant)
수천 개의 레퍼런스 영상에서 딱 맞는 장면을 찾아줌. "비 오는 카페 씬" 같은 검색어로 즉시 검색.
⭐
평점 시스템 (추천·랭킹 엔진)
연속성·스타일·실행가능성 등을 종합 점수로 매겨 최고만 추천. 품질 기준 미달이면 자동 탈락.
📜
조리법 변환기 (프롬프트 컴파일러)
Kling·Sora·Veo·Seedance 각각에 맞는 영상 생성 명령어를 자동 작성. 같은 장면도 엔진별로 최적화.

5. "연속성 점수" — Vivid의 북극성 지표

"개별 샷이 아무리 예뻐도, 이어 붙이면 어색하면 의미 없다."

Vivid의 모든 추천은 연속성 점수(Continuity Score)를 최우선으로 합니다. 이것은 앞뒤 장면이 자연스럽게 이어지는지를 AI가 측정하는 점수입니다.

추천 점수 구성 비율

연속성 45%
미장센 20%
스토리 15%
감독 10%
실행 10%
연속성 점수 의미 처리 방식
🔴 0.60 미만 앞뒤가 어색 ❌ 자동 탈락 — 감독에게 보여주지 않음
🟡 0.60~0.79 약간 어색 ⚠️ 제한 배포 — "주의" 라벨 부착
🟢 0.80 이상 자연스러움 ✅ 기본 추천 — 상단 노출
왜 이것이 중요한가?
2026년 Kling 3.0, Seedance 2.0 등이 15초 이내 멀티샷 연속성은 자체 해결하기 시작했지만, 30초 이상의 장편 시퀀스에서는 여전히 캐릭터·배경·분위기가 들쭉날쭉합니다. Vivid는 이 문제를 모델 독립적 연속성 점수로 자동 검증하여, 진짜 "영화"처럼 보이는 장편 결과물을 만듭니다.

• Evrim Ağacı — Seedance 2.0 멀티렌즈 캐릭터 일관성 분석

6. A/B 실험 엔진 — 추천이 점점 똑똑해지는 이유

Vivid는 넷플릭스처럼 자동 실험(A/B 테스트)을 합니다.

flowchart LR
    subgraph "실험 대상"
        Q1["시놉시스 A vs B"]
        Q2["씬 진행 A vs B vs 혼합"]
        Q3["샷 시퀀스 A vs B"]
    end

    subgraph "보상 측정"
        R1["채택률 40%"]
        R2["수정 적었는지 20%"]
        R3["빠른 결정 20%"]
        R4["만족도 20%"]
    end

    Q1 --> R1
    Q2 --> R2
    Q3 --> R3
    Q3 --> R4

    R1 & R2 & R3 & R4 --> LEARN["🧠 학습 → 다음 추천 반영"]
쉬운 설명: "감독이 A안과 B안 중 어느 것을 더 자주 선택하는지"를 관찰하고, 다음에는 감독이 좋아할 가능성이 높은 안을 먼저 보여줍니다. 쓸수록 똑똑해지는 시스템 = 데이터 해자(moat).

7. 아키텍처 딥다이브 — OpenClaw 메모리 허브

"AI 조감독의 뇌는 OpenClaw다.
모든 기억·판단·학습이 이곳을 중심으로 흐른다."

OpenClaw는 2025년 말 등장한 오픈소스 에이전트 프레임워크로, 2026년 현재 가장 주목받는 자율 AI 인프라입니다. Vivid는 OpenClaw를 단순한 챗봇 도구가 아니라, AI 조감독의 "중앙 신경계"로 활용합니다.

OpenClaw가 Vivid에서 하는 역할

📥
입력 통합 허브
텔레그램·노션·웹 등 여러 채널의 감독 입력을 하나로 모으고, 정규화(표준 형식 변환)합니다. OpenClaw의 멀티채널 통합 기능을 그대로 활용.
🧠
프로젝트 메모리
감독의 취향·과거 피드백·프로젝트별 맥락을 영구 기억합니다. OpenClaw의 로컬 파일 기반 구조화 메모리(Markdown)를 활용하여 세션 간 맥락을 유지.
🤖
서브에이전트 위임
복잡한 작업(긴 영상 분석, 대규모 레퍼런스 검색)을 전문 서브에이전트에 비동기 위임합니다. 메인 에이전트는 감독과 대화를 계속하면서 백그라운드 작업 진행.
🔧
스킬 시스템 (Tool Calling)
Gemini·TwelveLabs·Qdrant·렌더 엔진 등 외부 도구를 모듈형 플러그인으로 연결합니다. LLM이 필요한 도구를 자율적으로 선택·조합하는 에이전틱 루프.

3단 메모리 설계

flowchart TB
    subgraph "Layer 1: 작업 기억"
        WM["현재 대화 컨텍스트"]
    end

    subgraph "Layer 2: 프로젝트 기억"
        PM["프로젝트별 씬/샷 히스토리
        감독 스타일 프로필
        피드백 이벤트 로그"]

투자 관점 핵심: OpenClaw를 메모리 허브로 쓴다는 것은, 감독이 Vivid를 오래 쓸수록 AI가 그 감독만의 "조감독"으로 진화한다는 뜻입니다. 이것이 경쟁사가 따라잡기 어려운 네트워크 효과의 핵심입니다.

9. 아키텍처 딥다이브 — 시네마틱 연속성 & 프롬프트 컴파일러

Vivid의 최종 출력은 "영화처럼 자연스러운 멀티샷 시퀀스"입니다. 이를 위해 두 가지 핵심 시스템이 협력합니다.

① 시네마틱 연속성 엔진

2026년 2월 기준, Kling 3.0은 6샷 멀티샷을 단일 프롬프트로, Seedance 2.0은 멀티렌즈 스토리텔링으로 15초 이내 연속 영상을 이미 잘 생성합니다. 그러나 30초~수 분의 장편 시퀀스에서는 여전히 캐릭터·배경·감정선이 흐트러집니다. Vivid는 모델에 의존하지 않고, 자체 연속성 검증 레이어로 장편 멀티샷의 품질을 보장합니다.

② 프롬프트 컴파일러 — 엔진별 최적화 번역기

같은 장면이라도 Kling·Sora·Veo 각각에 최적화된 프롬프트가 다릅니다. 프롬프트 컴파일러는 마치 번역기처럼 하나의 장면 설계를 각 엔진의 "언어"로 변환합니다.

강점 활용 속도·멀티샷·AI감독 사실적 물리·스토리보드 시네마틱 품질·4K
프롬프트 스타일 간결·키워드 중심 상세 내러티브·물리 묘사 영화적 톤·조명 디테일

실전 효과: 감독이 "비 오는 도쿄 옥상에서 싸우는 장면, 봉준호 스타일"이라고 한 마디 하면, AI가 4개 엔진(Kling/Sora/Veo/Seedance)에 각각 최적화된 프롬프트를 자동 생성하고, 연속성 점수가 가장 높은 결과물만 감독에게 보여줍니다.
