# SPEC Verify Command

입력: $ARGUMENTS (spec 파일명, e.g., "feature-name")

---

## 목적
서브에이전트가 SPEC 대비 구현 완료 여부를 자동 검증.

---

## 워크플로우

### 1. SPEC 파일 로드

```
.claude/specs/$ARGUMENTS.md 읽기
```

### 2. 검증 체크리스트 추출

SPEC에서 검증 항목 추출:
- 기능 요구사항 (FR-*)
- 비기능 요구사항 (NFR-*)
- 테스트 계획
- 파일별 변경사항

### 3. 구현 대조 검증

각 항목에 대해:

#### API 검증
```
- 엔드포인트 존재 여부
- 요청/응답 스키마 일치
- 에러 처리 구현
```

#### UI 검증
```
- 컴포넌트 존재 여부
- 필수 props 구현
- 에러/로딩 상태 처리
```

#### 테스트 검증
```
- 테스트 파일 존재
- 테스트 통과 여부
- 커버리지 충족
```

### 4. 검증 리포트 생성

```markdown
# 검증 리포트: [feature-name]

## 요약
- 전체 항목: X개
- 완료: Y개
- 미완료: Z개
- 완료율: XX%

## 상세

### ✅ 완료된 항목
- FR-1: [설명]
- FR-2: [설명]

### ❌ 미완료 항목
- FR-3: [설명]
  - 누락 사항: [상세]
  - 수정 제안: [상세]

### ⚠️ 주의 사항
- [경고 1]
- [경고 2]
```

### 5. 피드백 반영

미완료 항목이 있으면:
1. 피드백 내용 전달
2. 추가 구현 진행
3. 재검증

---

## 자동 검증 항목

| 항목 | 검증 방법 |
|------|---------|
| API 엔드포인트 | grep router |
| 컴포넌트 | find component |
| 테스트 | pytest --collect-only |
| 타입 체크 | pyright/tsc |
| 린트 | eslint/ruff |

---

## 완료 기준

- [ ] 모든 FR-* 검증 통과
- [ ] 모든 NFR-* 검증 통과
- [ ] 테스트 실행 성공
- [ ] 검증 리포트 생성
- [ ] SPEC 상태: `DONE`

---

## 검증 통과 시

```
🎉 SPEC 검증 완료!

다음 단계:
- git commit
- PR 생성
- 코드 리뷰 요청
```
